# research-workflow（研究流程入口）

其他 skill 的入口。它自己不做分析：先弄清用户要什么，列出这家公司已有哪些文件，让用户选一条流程，再按正确顺序运行对应的 skill，每一步的输出检查通过后才交给下一步。

## 约定（固定不变）

- **单一任务直接转交。** 请求已经明确是某一件事（「总结这份电话会」「估值一下」「检查我的逻辑」），不弹菜单，直接用那个 skill。
- **每一步都运行真正的 skill。** 读取该 skill 的 `SKILL.md` 并完整执行，包括它的校验脚本。这里不复述、不简化它的规则。某个 skill 没装，就说明是哪个并跳过这一步，不自己发挥。
- **选项。** 宿主有提问工具（可点选的选项）就用它；没有就给简短的编号列表，请用户回编号。开始工作前最多问两个问题。
- **语言**跟随提问；各 skill 保留自己的语言规则。
- **缺输入或被拒绝访问**：停下来问用户怎么处理；不说明就用更少的输入继续是不允许的。
- **不给买卖建议、不给目标价、不判断贵或便宜**——与下面每个 skill 的规则相同。
- **脚本**：`scripts/status.py 文件夹 [--ticker T] [--json]` 列出这家公司已有什么（电话会日志最新季度、速读、财务表、估值日期、投资判断最新季度和测算日期、磁盘上的 transcript）以及哪些已过期。Python 3，标准库，不联网。

## Step 0：现在到哪一步了

1. 确定公司（ticker）和研究文件夹 `{RESEARCH_ROOT}/{TICKER}/`。对话里已经说过就不再问。
2. 运行 `python scripts/status.py "{RESEARCH_ROOT}/{TICKER}"`。它给出的 "suggested" 只是起点，不是决定。
3. 文件夹不存在，说明是新公司：建议流程 A。

## Step 1：选择

用两三行说明现状，然后问一个问题，选项如下（建议的放第一个）：

| 选项 | 适用 | 按顺序运行的 skill |
|---|---|---|
| **A. 首次覆盖** | 新公司 | company-research（含 10 季财务表）→ earnings-call-reader 先读次新一次电话会、再追加最新一次 → company-valuation → investment-view（核心、季度块、按 valuation-brief 规则写的测算） |
| **B. 新季度** | 有新的电话会 | earnings-call-reader（追加）→ quarterly-financials-dashboard（更新）→ company-valuation（按当天股价更新）→ investment-view（新季度块放最上面 + 新测算） |
| **C. 加一个会议** | 投资者日、OFC / ECOC、券商会议、会议纪要 | investment-view 的会议步骤（中英交替的稿子先拆分） |
| **D. 找标的** | 一个业务或一条产业链，而不是一家公司 | stock-discovery → 可选 value-chain-bom 或 architecture-delta-table → 对已有研究的公司做 company-comparison |
| **E. 复核** | 用户有自己的投资逻辑，或想并排比两家公司 | thesis-check，或 company-comparison |

A 和 B 里单独的 earnings-digest 是可选的：investment-view 已经按 earnings-digest 的规则写五维，只有用户想要那份一页纸速读文件时才单独跑。

然后，在同一个问题里（工具支持多选时）或作为第二个问题，给出**附加项**（默认不选）：

| 附加项 | 需要 | 运行 |
|---|---|---|
| 1. 与我的手写版对比 | 用户自己写的同一季判断 | 仓库的 `evaluation/`（`run_eval.py` → 一份新的实验报告） |
| 2. 稳定性检查 | 该步骤约 2 倍的成本 | 在全新会话里把选中的步骤跑两次 → `evaluation/stability.py` |
| 3. 成本质量记录 | 本次运行的 token / 用时报告 | `cost-benefit/cost.py add` → `table` |
| 4. 规则修改建议 | 已在 2 家以上公司做过附加项 1 | skill-tuner（只提建议，每处修改都由用户批准） |

附加项需要仓库（`evaluation/`、`cost-benefit/`）。拿不到就说明，并问是否不带附加项继续。

## Step 2：先给计划，再执行

1. 一条简短的计划：有哪些步骤、每一步找到了哪些输入、缺什么、选了哪些附加项。缺输入（新季度没有 transcript、附加项 1 没有手写判断）时，先问再开始。
2. 按顺序执行。每一步之后：
   - 它的校验必须 PASS；FAIL 按该 skill 自己的规则修好再往下走；
   - 下一步读上一步写出的文件，而不是它的摘要；
   - 只追加的文件（电话会日志、投资判断）在 `--before` 检查通过前保留备份。
3. 某一步失败两次，或需要只有用户能做的决定（判断标记、缺来源），停下来问，不跳步。

## Step 3：交付

- 一张表：步骤、skill、写出的文件、检查结果。
- 流程 A 和 B：下一份财报之前最值得盯的一件事（取自新季度块的下一季超预期点）。
- 附加项的结果和报告链接。
- 文件按各 skill 自己的方式交付；本 skill 不改动它们的内容。

## 这个 skill 不是什么

- 不是程序：每一步都由助手一个 skill 一个 skill 地执行，用户随时可以停下或改方向。
- 不放分析规则：规则属于使用它的那个 skill，只存在一份。
