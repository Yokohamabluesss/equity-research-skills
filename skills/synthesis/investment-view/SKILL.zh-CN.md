# Investment View（投资判断）

每家公司一份文件，任何时候都能回答：**这家公司是什么、靠什么增长、有什么新东西、上一季怎么样、下一季可能在哪里超预期、其他会议改变了什么、估值怎么说。** 它在研究流程的最顶层：earnings-call-reader 读电话会，earnings-digest 下判断，valuation-brief 浓缩估值模型，本 skill 把判断集中、精简地保持在最新状态。

> 本 skill 以手写的判断文件为基准校准过，仍在持续调整；版本记录见仓库根目录的 `CHANGELOG.md`。

## 约定（固定不变）

- **文件**：`{RESEARCH_ROOT}/{TICKER}/{TICKER}_投资判断.md`（中文）或 `{TICKER}_Investment_View.md`（英文）。任一已存在就更新那一份，并沿用其语言。旧文件名（`{TICKER}_财报前瞻判断.md`、`{TICKER}_Company_View.md`）也能识别：只有旧名文件时，原地更新，并询问用户是否改名。
- **语言**：新文件跟随提问语言（中文 → `_投资判断.md`，英文 → `_Investment_View.md`）；已有文件沿用其自身语言。固定字符串两种语言都有（见下表），`check_view.py` 两种都能检查。
- **建立在两个 skill 之上**：每个季度块的五维和"其他"按 **earnings-digest** 的规则写，测算按 **valuation-brief** 的规则写。调用这两个 skill；它们的规则只有一份，这里不重复。它们直接写进本文件，不另外生成速读或估值速读文件。同一季度 / 日期的速读或估值速读已经存在时，直接搬过来，不重写。任一 skill 没有安装时，告诉用户并空出那一部分，不要自己发挥。
- **风格——大纲，不是段落**：Tab 缩进，一行一个意思，用短语不用整句（中文每行尽量 ≤ 40 字）。逻辑靠层级表达：上级是判断，下级是证据。只有网格更清楚时才用表格（产品表、产能、产业链）。
- **核心中英双语（中文文件）**：核心的每条一级内容先写中文，下一行写同一句的英文；下级要点用中文，英文术语保留原样。措辞要紧的地方保留简短英文原话。
- **季度标签** `FY{YY} Q{n}`（财年），**日期** `YYYY-MM-DD`。写全日期很重要：每个季度块、会议记录和测算都是时点记录，以后可以拿来对照实际发生了什么。
- **时点板块只追加**：季度块、会议记录、测算一旦写下就不再修改。新的放在各自板块最上面（最新在前）。只有「核心」是持续更新的板块（见 Step 4）。
- **固定字符串**（不得改写）：

| 元素 | 中文文件 | 英文文件 |
|---|---|---|
| 核心块 | `# 核心` | `# Core` |
| 核心标签 | `特殊点`（可选）· `增长主驱动` · `新叙事` | `Special traits` · `Main growth drivers` · `New narrative` |
| 季度块 | `{TICKER}_Earnings.md` 最新一季：五维和"其他"按 earnings-digest 的规则写（或搬已有速读的财报会议块）；超预期点、总判断和表格由本 skill 写 | 先跑 earnings-call-reader；绝不凭记忆写季度块 |
| 季度标签 | `下一季超预期点` · `判断：{总判断}` | `Next-quarter upside drivers` · `Verdict: {overall}` |
| 五维（按顺序） | `财务` · `细分产业` · `订单` · `客户` · `业绩节奏` | `Financials` · `Sub-industry` · `Orders` · `Customers` · `Momentum` |
| 补充 | `其他` | `Other` |
| 会议 | `# ---其他会议---` | `# ---Other Events---` |
| 测算 | `# ---测算---` → `指引` · `假设` · `结论` | `# ---Estimates---` → `Guidance` · `Assumptions` · `Conclusion` |
| 自由笔记（用户维护） | `# 其他说明` | `# Other Notes` |

- **块顺序**：核心 → 季度块（最新在前）→ 其他会议 → 测算 → 其他说明。
- **脚本**（`scripts/`，Python 3，不联网）：
  - `check_view.py 文件 [--before 旧文件]`——结构、标签、判断标记、日期、顺序、行长度，以及"只追加"规则。另外对最新季度块运行 earnings-digest 的五维检查，对最新测算条目运行 valuation-brief 的检查（`check_digest.py` 和 `check_brief.py` 由 `tools/build.py` 复制到这里，检查规则保持完全一致）。
  - `split_bilingual.py 文件 -o 输出`——中英逐段交替的 transcript 只保留英文（在一份真实的发布会 transcript 上少约 25% 字符）。
- **校准**（与手写判断对比）不属于日常运行，放在仓库的 `evaluation/` 文件夹。

## 输入（优先复用）

| 文件中的部分 | 来源 | 缺失时 |
|---|---|---|
| 核心 | `{TICKER}_Earnings.md`（所有季度）、`{TICKER}_速读.md` / `_Digest.md`（逻辑和叙事）、首次研究笔记 | 按下面的 earnings-digest 规则从电话会日志写 |
| 季度块 | `{TICKER}_Earnings.md` 最新一季；有速读时用速读的财报会议部分 | 先跑 earnings-call-reader；绝不凭记忆写季度块 |
| 其他会议 | 用户提供的会议 transcript / 纪要 / 幻灯片 | 请用户提供文件；不去网上搜"说了什么" |
| 测算 | 按 valuation-brief 的规则读 `{TICKER}_Valuation_Dashboard.xlsx`（或搬已有的 `{TICKER}_估值速读.md` / `_Valuation_Brief.md`） | 保持原样，建议先跑 company-valuation |

五维的判断规则只在 earnings-digest 里，测算规则只在 valuation-brief 里；在那里改规则，这里自动生效。

## Step 0：确定本次要做什么

以下一项或几项：

- **A. 新季度**——`{TICKER}_Earnings.md` 里有判断文件还没有的季度 → Step 1–4。
- **B. 会议**——用户给了会议文件或纪要 → Step 5。
- **C. 新测算**——估值速读 / 估值表比最新一条测算更新 → Step 6。
- **D. 只刷新核心**——用户要求修订核心 → Step 4。

判断文件已存在时，先复制为 `{原文件名}.backup.md`。

## Step 1：核心（新建文件，或在 Step 4 修订）

```
# 核心
{一句话定位：它是谁、在产业链哪一层、凭什么不可替代；写成转变时用"从 X 到 Y"}
{同一句的英文}
	{支撑定位的事实：份额、客户覆盖、营收结构}
	{English}
特殊点                      ← 只有当某个特点改变了读这家公司的方式时才写
	{例：供需完全由终端决定；放量节奏跟随下游}
增长主驱动
	{驱动 1：产品 / 终端市场}
		{下游客户、为什么增长、可见度}
	{驱动 2}
新叙事
	{叙事 1}
		{之前 → 之后：以前为什么进不去、现在为什么打开了}
		{最硬的证据：产品、收购、首笔收入 / 指引、点名客户}
		{为什么重要：机制，如"CPO 良率要求高，所以测试是刚需"}
```

规则：
- **核心是摘要，不是报告**：约 8–15 行，外加一张可选的结构表。少放数字——数字放在季度块里。
- **定位写产业链位置，不写公司简介。** 说清在哪一层、做什么不做什么；来源支持时，把公司放进它所在的梯队并点名同业（如"硅光 PIC 代工第一梯队，同梯队还有 …"）。
- **增长主驱动要回答"钱从哪来"**：产品或终端市场、下游客户、为什么在增长。
- **新叙事 = 还没体现在数字里的东西。** 每条写清变化了什么（之前 → 之后）、目前最硬的证据、所处阶段（送样 / 首单 / 首笔收入 / 已给指引）。没有就写 `本季无新增`。
- 结构表（产业链、垂直整合图）只有在比文字更清楚、且每一格都有来源支持时才用。
- 推测要标 `推测：`（例："推测是 AMD"）。

## Step 2：季度块

```
# ---FY26 Q2--- 超预期，{一句话阶段，如"Q1 刚进入放量期"}

下一季超预期点
	{驱动 1，附证据和时点}
	{驱动 2}
判断：{一句总判断}
	✅️财务：{判语，如"S 曲线加速中"}
		{2–4 个要点}
	✅️细分产业：{判语}
		{按产品线分条：产品 → 产业阶段 / 供需 / 为什么能起量}
	⚠️订单：{判语}
		{backlog / 合约 / LTA / 可见度；口径限定词照抄}
	✅️客户：{判语}
		{按产品线分条：客户 → 节点变化；消失的客户}
	✅️业绩节奏：{判语}
		{按产品线分条：只写相对上季的变化，带 🔼 🔽 🆕 ➡️ ⚠️ 📌}

| 产品 | 当前节点 | 预计放量时间 | 预计贡献体量 |
|---|---|---|---|
{电话会日志最新一季的 Product Summary Table}

{可选：供给受限时附产能 / 稼动率 / 里程碑表}
其他
	{供给约束、扩产计划、定价、一次性项目}
```

怎么写：
- **Tag**：按实际值 vs 指引和一致预期写 `超预期 / 符合预期 / 不及预期`，再用一句短语写周期阶段（"Q1 刚进入放量期"、"爬坡中，2027 放量"）。
- **下一季超预期点**（1–3 条）：可能让下一份财报超预期的具体变量——产能爬坡速度、利润率的台阶、新产品首笔收入、已指引的里程碑——每条附证据和预计时点。这是季度块里前瞻的部分，下一季的季度块要拿它来对照。
- **判断**：一句话，五个标记要能支撑它。
- **五维和"其他"**：按 earnings-digest 的规则写（每一维写什么、判断标记和全 ✅️ 复查、财务维 2–4 个锚点数字、业绩节奏只写变化、按产品线分条）。和速读唯一的区别是版式：这里用上面的大纲（Tab 缩进的子项，不加粗），"其他"放在表格之后。
- **产品表**：电话会日志最新一季的 Product Summary Table。**投资逻辑所涉及产品线的每一行、每个子行都保留**，单元格照日志原样（包括 🆕 🔼 ⚠️）；与投资逻辑无关的板块的行删掉，最多在 `其他` 里留一行。不编造单元格。
- **产能表**：供给是约束时，把日志里的产能表格原样搬过来——按厂的稼动率（带 vs 上季列）、扩产路线 / 阶段、产能里程碑及原话。
- **数字和引用**：每个数字都来自电话会日志；每个要点最多一句简短原话。

## Step 3：放置

新季度块插在**上一季度块之上**（紧接在核心下面）。旧季度块一律不改——发现旧内容有误，在新季度块里说明。

## Step 4：复核核心（持续更新的板块）

新季度或新会议之后，逐条对照新证据检查核心：

- 仍然成立 → 保持原样，措辞不动（这是用户的措辞）
- 被加强或被量化 → 在下级加一行新事实，标 🔼 或 🆕
- 被削弱或被反驳 → 保留原行，在下级加一行以 ⚠️ 开头写明冲突；不删用户的行
- 出现新驱动或新叙事 → 加一条并标 🆕

在对话回复里列出核心的每一处改动（"核心：新增 🆕 …；标注 ⚠️ …"），方便用户接受或撤销。

## Step 5：其他会议（电话会以外的材料）

包括投资者日 / 分析师日、产品发布会和展会活动（OFC、ECOC 等）、券商会议上的炉边对谈、管理层会议纪要、调研、新闻稿。

1. **确定会议信息**：公司、会议名称、日期、发言人——从文件开头读。日期或公司不清楚时问用户。确认是同一家公司（注意相近的名字）。
2. **中英交替的 transcript**（一段英文接一段中文翻译）：`python scripts/split_bilingual.py 文件 -o 文件.en.txt`，读英文部分；译文不是信息源。中文会议纪要直接读。
3. **信息源权重**：管理层公开发言（发布会、投资者日、会议）按电话会同等对待并可引用；券商会议纪要和二手纪要标注 `（纪要口径）`，绝不当作指引。
4. **把条目写在 `# ---其他会议---` 最上面**：

```
# ---其他会议---
2026-09-23
	ECOC — PhotonLink 发布会（CEO / CTO / EVP）
		客户合作：CPO >10 个、NPO >10 个、chip-to-chip >5 个
		CPO/NPO
			进度：未改变                ← 每个主题的第一行：相对当前判断的变化
				scale-out CPO 2026Q4 量产；scale-up CPO 2H27；NPO 2H27（LTA 核心客户）；chip-to-chip 2029–2030
			CW：与两家头部 AI hyperscaler 签 LTA，覆盖 CPO 与 NPO
			ELS：送样中
		{其他主题：产品、产能、TAM / 单系统价值量（标注为管理层口径）}
```

   - **每个主题第一行写相对当前判断的变化**：`进度：未改变 / 提前 / 推迟 / 🆕`。会议值得记录，主要是因为它改变了什么。
   - 然后只写投资逻辑相关的新事实：数量、时间表、LTA、投资逻辑所依赖组件的送样 / 量产状态。
   - 管理层的 TAM / 单系统价值量说法最多写一行（标注为管理层口径）。
   - 条目要短，约 10–20 行。不写组件清单和营销叙事。
5. 如果会议改变了核心的某一条或某个下一季超预期点，按 Step 4 处理核心，并在回复里说明影响了哪个超预期点。不改季度块。

## Step 6：测算

在 `# ---测算---` 最上面加一条带日期的条目，格式同 valuation-brief。条目日期是调用 skill 的当天，股价是当天最新价（速读或估值表较旧时按 valuation-brief 的做法刷新）：

```
# ---测算---
2026-10-14（股价 $209.16）
	指引
		{下一季指引；长期目标 / 里程碑}
	假设
		{营收路径及来源}；{利润率路径}
	结论
		{① 营收路径来源与指引覆盖率；保守程度}
		{② 利润率路径及长期目标达成时点的判断}
		{③ FY cur PE + EPS 增速；FY+1 PE + EPS 增速；PEG；FCFF 反推}
		{④ 与一致预期的差距及来源}
```

按 valuation-brief 的规则写这条（调用该 skill）：读估值表的 Conclusion 和 PE & PEG 两页，按它的要求刷新股价，直接写进本节，不另外生成估值速读文件。同一日期的估值速读已经存在时，直接搬过来。**按原分辨率搬过来——这一节不再进一步压缩**：
- 指引写出区间的两端，以及公司不给哪些指引；
- 长期模型的金额和比例（营收、毛利、营业利润、净利、费用率）；
- 营收路径和利润率路径，模型里有逐季数据就逐季写；
- 利润率拆解（毛利率变化和费用率变化，全年口径与单季退出口径）；
- 分年度的一致预期差距、按变量归因，加上一句话的分歧本质，以及一致预期相对上次测算的变化。

结论太长时，可以在 `结论` 后面加 `数值`、`一致预期` 两个标签。不说"贵 / 便宜"，写现价需要满足的条件。

## Step 7：检查与交付

1. `python scripts/check_view.py 文件 --before 文件.backup.md`（首次运行不带 `--before`）。修掉新增部分的所有 FAIL；LEGACY 是旧条目的旧格式问题——报告一次，绝不改写。检查通过后删除备份。
2. 回复内容：新增了什么（季度 / 会议 / 测算）、核心的改动（Step 4 的清单）、下一份财报之前最值得盯的一件事。不要把整个文件贴出来。

## 规则

1. **事实只来自输入。** 数字、原话、客户名来自电话会日志、会议文件或估值材料——绝不凭记忆。
2. **判断要明确、有依据**；推测要标注。
3. **保留用户的原话。** 核心的行不改写；时点条目不修改。
4. **不给买卖建议、不给目标价。** 可以说超预期概率、"现价需要什么条件"，不说"便宜 / 值得买"。
5. **固定字符串**照抄上表。
