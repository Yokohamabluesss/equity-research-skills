# Stock Discovery（相关公司挖掘）

本 skill 用于解决一类高频的卖方/买方研究需求：「**这个赛道/产业链/名单里，到底有哪些上市公司做？每家做到什么程度？**」。它的目标是把"散落在年报、产业链调研、展会名单、招标公告、行业媒体"里的相关公司，**结构化、带产业地位标签**地汇总到一张 xlsx 表里。

## 约定（固定不变）

- **输出**：一律用 `scripts/build_xlsx.py`，并带 `--output "{RESEARCH_ROOT}/stocks/{文件名}"`（文件名见 Step 5）。脚本固定列顺序、校验标签列、对模式 1 做确定性排序，并生成 Summary 页。
- **语言**：JSON 里写 `"lang": "zh"` 或 `"en"`，跟随用户提问的语言；表头、标签、Summary 页随之切换。JSON 的键可以用英文（推荐）或原来的中文键。
- **固定标签**——标签列必须**以下表某个标签开头**（后面可以跟简短限定，如 `二线（FAU 头部）`；更长的说明放备注）。其他写法会被脚本直接报错，而不是静默漏色：

| 列 | 中文 | 英文 |
|---|---|---|
| 产业地位 | 头部 / 二线 / 新进入者 / ⚠️ 待确认 / 下游需求侧 / N/A | Tier 1 / Tier 2 / New entrant / ⚠️ TBC / Demand side / N/A |
| 产品阶段 | 量产 / 送样 / 研发 / 概念 / N/A | Mass production / Sampling / R&D / Concept / N/A |
| 市场关注度 | 高 / 中 / 低 | High / Medium / Low |
| 业务相关性（模式 3） | 是 / 部分 / 否 / ⚠️ 待确认 | Yes / Partial / No / ⚠️ TBC |
| 环节层级（模式 2） | 上游 / 中游 / 下游 | Upstream / Midstream / Downstream |

## 三种模式 (Three Modes)

进入 skill 后，**第一件事是判断当前请求属于哪种模式**——三种模式的搜索路径、产出粒度、表格列都不一样。判断不出来就直接问用户。

| 模式 | 触发场景 | 重点 | 表格主键 |
|---|---|---|---|
| **① 业务挖掘 (Business Discovery)** | 用户给一个**具体业务**（大如 CPO / 小如 FAU / 微如 850nm VCSEL）—"挖一下做 XX 的公司" | **覆盖广度**——尽可能多地挖出做这个业务的公司 | 公司 |
| **② 产业链梳理 (Industry Chain Mapping)** | 用户给一个**产业链**（DCI / 800G 光模块 / 固态电池 / AI 服务器）—"梳理一下 XX 上下游" | **链条完整性**——上中下游每个环节都要覆盖到，每个环节 1-2 家主玩家 | 产业链环节 |
| **③ 清单筛选 (List Screening)** | 用户给**一份公司清单 + 一个业务方向**——"OFC 2026 参展商里做光通信的有哪些" | **逐家定位**——清单里每家公司对应业务的实际做的什么、做到什么程度 | 公司（按用户给的清单顺序） |

详细的每个模式的搜索套路和表格格式见 `references/mode-1-business-discovery.zh-CN.md`、`references/mode-2-industry-chain.zh-CN.md`、`references/mode-3-list-screening.zh-CN.md`，**触发后先 Read 对应的 reference**。

## 共通工作流 (Shared Workflow)

无论哪种模式，都按下面的顺序走。

### Step 0：判断模式 + 确认范围 (Identify Mode & Scope)

**判断模式**——按上面表格的触发场景对号入座。如果含糊（例如用户说"AI PCB 上下游"——既像产业链又像业务挖掘），**简短问一句**："你想看的是 ① 谁做这个业务（覆盖广度优先），还是 ② 整条产业链上下游每环节谁做（链条完整性优先）？"

**确认市场范围 (markets)**——默认 **A 股 + 美股**。如果用户明确说了"只看 A 股"或"加上港股"，按用户的来。如果用户没说，就按默认走，**不要反问**。

**确认业务关键词 (segment keywords)**——把用户给的赛道词转成**搜索可用的产品级关键词**。例如：

- 用户说"光通信" → 搜索时拆成 `光模块 / 光器件 / EML / CW laser / DFB / VCSEL / 硅光 SiPh / FAU / TEC / 隔离器`
- 用户说"AI 服务器" → 拆成 `GPU 模组 / HBM / NVLink / CCL / AI PCB / 液冷板 / BBU / 电源模块`
- 用户说"固态电池" → 拆成 `硫化物电解质 / 氧化物电解质 / 聚合物电解质 / 锂金属负极 / 干法电极设备`

**这一步极其重要——拆得越细，挖到的公司越全**。如果不确定怎么拆，先用一次 web search 看行业是怎么拆的（搜 `{赛道} 产业链 主要环节` 或 `{segment} value chain key components`）。

### Step 1：广撒网搜索 (Broad Search)

用多角度搜索，**不要只搜中文或只搜英文**。常用搜索套路：

1. **直接搜赛道 + 上市公司**：
   - 中文：`{业务} A 股上市公司`、`{业务} 标的`、`{业务} 龙头`、`{业务} 概念股`
   - 英文：`{segment} public companies`、`{segment} suppliers stock`、`{segment} key players`

2. **搜公司年报/招股书的招标披露**——这是**最硬的来源**，公司自己说的：
   - `{业务关键词} 主要客户` / `{业务关键词} 主要供应商`
   - `{segment} customer` / `{segment} supplier 10-K`

3. **搜产业链调研报告（券商研报、第三方咨询）**：
   - `{业务} 产业链 研报`、`{segment} industry report`、`{segment} market research TrendForce / Yole / Omdia`

4. **搜展会 / 标杆客户的供应商名单**：
   - `{标杆客户} 供应商 {业务}`（如"NVIDIA 光模块 供应商"、"宁德时代 固态电解质 合作"）
   - `OFC / CES / SEMICON / 慕尼黑光博会 / 高交会` 的展商名单

5. **反向搜——从下游往上**：
   - 找下游已知的几家公司（如 NVIDIA / 中际旭创 / 宁德时代），搜它们的供应商
   - 这一步往往能挖到容易被忽略的隐形冠军 (hidden champion)

**搜索时记笔记**——每搜到一家相关的就记下来：公司名、ticker、所属市场、相关产品线索。**不要在搜索阶段就过滤**——宁可多记几家后面再砍。

### Step 2：逐家核实 (Per-Company Verification)

对每家挖到的公司，**必须**核实下面三件事，否则不要写进表里：

1. **业务真的存在吗？** ——公司公告、年报、官网产品页、IR 材料里有没有这个业务的明确表述。如果只是某篇研报或某个论坛帖子说有，但官方材料里查不到，**降级标注为「⚠️ 推测 (speculation)」**。
2. **产品做到什么阶段？** ——必须在下面四档里选一个：
   - **量产 (mass production / MP)**：已经出货、有收入贡献
   - **送样 (sampling / customer trial)**：已经送样验证，未规模量产
   - **研发 (R&D / development)**：在研，未送样
   - **概念 (concept / disclosed only)**：只在公告/路演里提到过，未见实际产品或研发投入
3. **在这个业务上的产业地位 (position)**——必须在下面三档里选一个：
   - **头部 (Tier 1 / leader)**：行业前几家、市占率明显领先、被下游 KA 客户认可
   - **二线 (Tier 2 / follower)**：有产品有客户，但规模和地位明显落后于头部
   - **新进入者 (new entrant / emerging)**：刚切入、客户认证中、收入贡献几乎为零

**地位判断的依据**——优先看下游大客户的供应链份额披露（如苹果产业链、台积电产业链），其次看公司自己的市占率说法（带怀疑），最次看券商研报的"龙头/二三线"描述。**如果资料不够，宁可标"⚠️ 待确认 (TBC)"**。

### Step 3：评估市场关注度 (Market Attention)

每家公司都要标 **高 / 中 / 低**。综合下面三个维度：

| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| **券商覆盖** | ≥10 家券商出研报 | 3-9 家 | <3 家或仅地方小券商 |
| **散户讨论** | 雪球/股吧/Twitter/Reddit 高活跃，常上热搜 | 有讨论但不集中 | 几乎无讨论 |
| **新闻曝光** | 近 3 月频繁出现在主流财经媒体 | 偶尔出现 | 几乎没有 |

三个维度的综合判断 → 一个 **高 / 中 / 低** 标签。**不要展开三档分别打分**，太碎。

### Step 4：标注涨幅滞后 (Underperformance Flag) ⭐

这是本 skill 的特色信号——找出**做相关业务、但股价相对板块没怎么跟涨**的标的（可能被市场忽视，也可能是基本面有问题，反正先标出来）。

**判断方法**：
1. 找一个该业务的板块代表（A 股可用对应概念指数或行业 ETF；美股用同业龙头如 LITE / CRDO 之类）作为 benchmark。
2. 看公司**近 3 个月 / 近 6 个月 / 年初至今 (YTD)** 涨幅 vs benchmark。
3. 如果该公司有明确的相关业务**且**至少有两个时间窗口的涨幅显著低于 benchmark（比如 benchmark +30% YTD，公司 +5% 甚至下跌），打上 **🐢 涨幅滞后** 标签，并在备注里写明对比基准和涨幅差。

**没必要每家都查涨幅**——优先查那些"业务有、地位还行、市场关注度低或中"的标的，这些最可能是被忽视的。

**不要做估值判断**——本 skill 不算 PE / PB / 不给目标价 / 不喊买卖。涨幅滞后只是**信息标签**，不是推荐。

### Step 5：输出 xlsx (Output)

调用 `scripts/build_xlsx.py` 生成 xlsx 表格。脚本接收一个 JSON 文件作为输入，用 `--output` 输出到 `{RESEARCH_ROOT}/stocks/`：

```bash
python scripts/build_xlsx.py rows.json --output "{RESEARCH_ROOT}/stocks/CPO_相关公司_20260508.xlsx"
```

脚本报标签错误时，改标签（或把限定说明挪进备注）后重跑，不要改脚本。英文输出的文件名：`{业务}_Companies_{YYYYMMDD}.xlsx` / `{产业链}_Value_Chain_{YYYYMMDD}.xlsx` / `{清单名}_{业务}_{YYYYMMDD}.xlsx`。

**文件命名规范**：

- 模式 1（业务挖掘）：`{业务}_相关公司_{YYYYMMDD}.xlsx`，例如 `CPO_相关公司_20260508.xlsx`
- 模式 2（产业链梳理）：`{产业链}_产业链_{YYYYMMDD}.xlsx`，例如 `DCI_产业链_20260508.xlsx`
- 模式 3（清单筛选）：`{清单名}_{业务}_{YYYYMMDD}.xlsx`，例如 `OFC2026_光通信_20260508.xlsx`

**xlsx 输出的具体列结构** 见各 mode 的 reference 文件。脚本调用方式见 `scripts/build_xlsx.py` 顶部注释。

#### 子环节分布速览 (Segment Overview) ⭐

每个 `row` 都可以带一个**可选**字段 `子环节`（不属于主表的 9/10/9 列固定 schema，**只用于 Summary 页的速览渲染**）。当任意一行带了这个字段时，`build_xlsx.py` 会自动在 Summary 页"总结/关键洞察"和"说明"之间插入一张「子环节 × 产业地位」的速览表，让用户打开 Summary 就能看到整条赛道的玩家分布。

**强烈建议在模式 1（业务挖掘）输出时给每行打上 `子环节`**——业务挖掘的产物天然横跨多个材料/产品子环节（如 Low-CTE CCL 体系 = CCL 整板厂 / 球形硅微粉 / Low-CTE 玻纤布 / Low-CTE 树脂 / HVLP 铜箔 五个子环节），速览表比一堆细行更直观。

**模式 2（产业链梳理）** 自身就有 `子环节` 列，速览表也会自动渲染（主表的 `子环节` 列就直接被复用，不需要额外字段）。

**模式 3（清单筛选）** 默认不渲染速览表，除非用户明确要按某个分类维度看分布——这种场景下也可以在 row 里加 `子环节`。

**示例 row（模式 1，加上 子环节）**：

```json
{
  "公司名": "联瑞新材 Novoray",
  "Ticker": "688300.SH",
  "市场": "A 股",
  "相关产品": "球形硅微粉",
  "产业地位": "头部",
  "产品阶段": "量产",
  "市场关注度": "高",
  "涨幅滞后": "",
  "备注": "...",
  "子环节": "球形硅微粉（Low-CTE 填料）"
}
```

`子环节` 字段在主表（Companies sheet）里**不会显示**——它只参与 Summary 页的速览渲染。子环节命名要**前后一致**（不要一行写"球形硅微粉"另一行写"球硅"），脚本是按字符串精确分组的。

## 共通规则 (Shared Rules)

1. **数据要有出处 (cite everything)**——每家公司的关键标签（业务、阶段、地位）至少有一个明确出处。如果无法核实，**降级或不写**，不要硬编。备注列里写出处即可（公司公告 / 10-K / 券商研报名 / 媒体报道链接）。
2. **推测要标注 (mark speculation explicitly)**——基于产业链上下游、招标信息、客户配套关系倒推的，必须写明 `⚠️ 推测：……`。
3. **不要漏掉 ADR / 港股 H 股的双重上市情况**——例如台积电 (TSM)、阿里 (BABA / 9988.HK)、宁德 (300750.SZ / 3750.HK)。优先列流动性最好的那个市场，其他在备注里提一下。
4. **A 股写带后缀的代码**：`300750.SZ`、`688981.SH`、`002463.SZ`。**美股写裸 ticker**：`NVDA`、`LITE`。**港股**：`9988.HK`、`3750.HK`。
5. **不写市值 (market cap)、PE、目标价**——本 skill 是挖掘和筛选，不是估值。**唯一**和价格相关的字段是 Step 4 的"涨幅滞后"标签。
6. **覆盖广度的取舍**：
   - 模式 1 默认列 **8-15 家**，挖到再多也按"头部 → 二线 → 新进入者"的顺序（脚本会排序），每档不超过 5-7 家。
   - 模式 2 每个环节 **1-2 家**主玩家足矣，**不要堆**。链条本身的完整性比每个环节列多少家更重要。
   - 模式 3 给多少列多少（清单是用户定的），但**没找到任何相关业务的公司也要保留在表里**，标注「无相关业务 (no relevant business)」，这样用户能看到"没漏处理"。

## 触发后立即做什么 (Immediate Action After Trigger)

1. 用 `Read` 读对应模式的 reference 文件 (`references/mode-{1,2,3}-*.zh-CN.md`)
2. 按 Step 0 判断模式 + 确认市场范围 + 拆解业务关键词
3. 按 Step 1-4 工作流推进
4. 调用 `scripts/build_xlsx.py` 输出 xlsx 到 `{RESEARCH_ROOT}/stocks/`
5. 给用户一段简短的总结（不超过 300 字）+ xlsx 文件路径 / 链接

不要在对话里把整张表完整复述一遍——表已经在 xlsx 里了，对话里给摘要和洞察就够。
