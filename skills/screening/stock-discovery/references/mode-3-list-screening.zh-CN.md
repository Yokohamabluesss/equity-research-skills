# Mode 3：清单筛选 (List Screening)

## 目标

用户给一份**公司清单**（如 OFC 2026 参展商、CES 2026 参展商、某券商产业链调研名单、某 ETF 持仓名单）+ 一个**业务方向**（如"光通信"、"AI 算力"），要求逐家公司在该业务方向上的定位。

**重点是逐家定位 (per-company classification)**——清单是用户给的，本 skill 不挖新公司，只对清单里的每家公司做"业务相关性 + 产业地位"的逐一判断。

## 输入处理

清单可能以多种形式来：

- **直接的文本列表**（CSV / 一行一家）
- **附件文件**（xlsx / pdf / txt——用 Read 工具读）
- **URL 链接**（如展商页面——用 web search/fetch 抓取）

**清单可能很长**（几十到几百家）——必须**全部处理**，不能因为长就抽样。如果超过 200 家，提示用户："清单有 N 家，预计需要 X 分钟，是否继续？"

## 表格列结构 (xlsx Schema)

固定 9 列，**保持清单原始顺序**（不重新排序——用户的清单顺序往往本身有意义，比如展位号顺序）。

| # | 列名 | 内容 | 必填 |
|---|---|---|---|
| 1 | 序号 | 清单中的原始序号 | ✓ |
| 2 | 公司名 | 中英文公司名 | ✓ |
| 3 | Ticker | 带交易所后缀的代码；非上市公司写"未上市" | ✓ |
| 4 | 市场 | A 股 / 港股 / 美股 / ADR / 未上市 / 私有 | ✓ |
| 5 | 业务相关性 | 是 / 否 / 部分 / ⚠️ 待确认 | ✓ |
| 6 | 相关产品 | 公司在指定业务上的具体产品；无关写"-" | ✓ |
| 7 | 产业地位 | 头部 / 二线 / 新进入者 / N/A（无关时） | ✓ |
| 8 | 产品阶段 | 量产 / 送样 / 研发 / 概念 / N/A | ✓ |
| 9 | 备注 | 关键客户、为什么判定无关、佐证来源等 | ✓ |

**注意**：模式 3 的表格里**不需要**"市场关注度"和"涨幅滞后"列——这两个在筛清单的场景里不是核心信息。如果用户后续想看，可以单独问。

## 业务相关性的四档判断

| 档位 | 含义 |
|---|---|
| **是 (Yes)** | 公司有明确披露的、与指定业务直接相关的产品/技术，且是该业务收入的主要构成 |
| **部分 (Partial)** | 公司有相关产品，但只是其业务的一小部分（占比 <20% 或仅作为配套器件） |
| **否 (No)** | 公司主营业务与指定业务无明显重合 |
| **⚠️ 待确认 (TBC)** | 公开信息不足，无法判断 |

## 处理流程

1. **读清单 → 标准化**：把清单转换为统一格式（公司名 + 是否上市 + ticker）。先用一遍 web search 把没有 ticker 的公司补全。
2. **批量初筛**：先用业务关键词在每家公司的官网/年报快速扫一遍，标 是 / 否 / 部分 / 待确认。这一步**不深究地位**，只判断相关性。
3. **对"是"和"部分"的逐家深挖**：
   - 找具体产品名
   - 找下游客户线索（决定地位）
   - 找产品阶段（量产/送样/研发/概念）
4. **对"待确认"的兜底搜索**：再搜一轮——如果还查不到明确信息，**保留"待确认"标签**，不要硬给一个判断。
5. **对"否"的快速备注**：写一句话"该公司主营 XXX，与 {业务} 无关联"，方便用户复核。

## 常见陷阱

1. **被参展业务误导**——展会经常把不同业务混在一起（OFC 既有数通光模块也有相干通信也有 PON），不能因为公司参展 OFC 就认定它做"数通光模块"。必须看具体产品。
2. **代理商/分销商混入**——展会展商里常有代理商参展（如某些"测试设备代理"），这些**不是制造商**。判断"业务相关性"时只看制造端。
3. **大公司只展示某条产品线**——如三星 / 索尼这种大公司，参展光通信展会可能只是展某个细分产品，**不能因此说它"是光通信公司"**。要在备注里写明 "在 {业务} 内的相关产品仅占公司业务的 X%"。
4. **没找到也要标**——不能因为没搜到资料就略过某家。"⚠️ 待确认" 也是一个有效信号，提醒用户后续自己查或交给分析师。
