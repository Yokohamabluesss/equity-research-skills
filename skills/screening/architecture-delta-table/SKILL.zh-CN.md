# 架构迁移环节增减量对照表

## 这张表要回答什么

投资研究里最常被问错的问题是「新架构利好谁」。直觉答案总是「做新东西的公司利好」，但真实结构复杂得多：

- 有些环节是**纯新增**——旧架构里根本不存在这个位置，做这个的公司没有历史包袱
- 有些看着像增量，其实是**平移**——总量没变，只是换了位置或形态（最容易被误判成利好）
- 有些公司**内部抵消**——丢掉一块拿到一块，净影响接近中性，不能简单算利好
- 有些环节在**不同新路线之间方向相反**——押 A 路线则完全不受益，押 B 路线则是核心增量，这是投资上真正需要做选择的地方

这张表的价值就在于把这四种情况分开。做得好的标志是：**用户看完能指出哪几行是路线互斥点，以及哪几家公司是「完全没有内部抵消」的纯受益标的**。

## 约定（固定不变）

- **用脚本建表**：`python scripts/build_delta_xlsx.py input.json output.xlsx`，不要手写 openpyxl（以前脚本嵌在本文件里，每次都要重新写出来，既费 token 又可能写走样）。
- **语言**：JSON 里 `"lang"` 跟随用户提问的语言。
- **文件名**：中文 `{基准架构}到{路线A}_{路线B}_环节增减量_{YYYYMMDD}.xlsx`，英文 `{baseline}_to_{routeA}_{routeB}_Segment_Delta_{YYYYMMDD}.xlsx`，放在 `{RESEARCH_ROOT}/stocks/`。

## 第 1 步：确认基准与路线

先明确三件事，缺一不可：

1. **基准架构**（旧的、被替代的那个）——所有增减都是相对它算的
2. **新路线**，默认 2 条，支持 1 条或 3 条以上。用户如果只说了一条，问一句是否还有并行路线——大多数架构迁移期都不止一条（可插拔→LPO/NPO/CPO、液态→半固态/全固态、冷板→浸没）
3. **基准机型或基准场景**——没有具体机型就没法算用量。「英伟达 Quantum-X Photonics Q3450-LD，115.2Tb/s，144×800G」比「一台 CPO 交换机」有用得多

没给基准机型就先搜一个有公开规格的代表性产品，并在表头注明。

## 第 2 步：拆环节，重点是防漏

沿**信号链 / 能量链 / 物料链**从头到尾走一遍，不要只列"主角"。按这九类各问一句「这个架构迁移动到它了吗」：

| 类别 | 为什么容易漏 |
|---|---|
| 1. 核心功能器件 | 不会漏，这是主角 |
| 2. 上游材料与衬底 | 最上游、供给弹性最差，常是全链条唯一有物理上限的环节 |
| 3. **制造设备与工艺** | **最容易整个环节漏掉**——新架构常引入全新工艺，设备商是纯新增受益且格局极集中，但不在 BOM 里 |
| 4. 封装与集成 | 架构迁移的本质往往就是集成度变化，几乎必然有变动 |
| 5. 连接与结构件 | 形态变了就是新料号，全球格局通常比主环节更集中 |
| 6. **测试与良率** | 不可返修的架构会迫使测试前移，需求天然领先于器件出货，适合当领先指标 |
| 7. 散热、供电、机械 | 密度提升的必然结果 |
| 8. 软件/控制/算法芯片 | 有些迁移会**消灭**一整类芯片（如去 DSP），这是最确定的减量 |
| 9. 组装与代工 | 内部抵消或减量的重灾区，别忘了列 |

先列 20-30 行，宁多勿少。真没内容的行删掉比事后补容易。

### 光通信：可插拔 → NPO / CPO / LPO（经实盘核对的清单，可直接起步）

**光引擎与芯片**：硅光引擎 PIC｜调制器（EML 直调/硅光 MZM/微环 MRM/TFLN）｜Driver/TIA｜DSP（**去 DSP 是最确定的减量**）｜Retimer｜交换 ASIC
**光源**：CW 激光器芯片（与 EML 是不同产品，别混）｜ELSFP 外置激光模块｜ELSFP 连接器与笼子（**独立于光源模块本身，极易漏**）｜Micro TEC 温控
**无源光学**：FAU 光纤阵列｜微透镜阵列/耦合光学｜AWG/Mux-Demux（合波功能可能被集成进 PIC，分立件需求存疑）｜MPO/MT 插芯｜Shuffle Box｜保偏光纤 harness｜隔离器（核心料是法拉第旋转片/TGG）
**基板与板级**：载板/封装基板｜PCB 高速铜走线（减量）｜高速电连接器（板对板/封装体 socket/光背板/盲配）
**设备材料测试**：InP 衬底｜混合键合设备（**CPO 需要、NPO 不需要——典型路线互斥点**）｜光纤耦合对准设备｜PIC 晶圆测试 KGD｜散热液冷
**被替代**：可插拔模块壳体/组装

光通信特有要点：MPO 通常是平移不是增量（端口总数没变），真增量在保偏 MPO 与 Shuffle Box｜EML 属可插拔、CW 属 CPO/NPO，两者共用 InP 产能所以互相挤兑但需求方向相反｜CPO 价值量大量落在代工厂体系内（台积电 COUPE 把 PIC+EIC+混合键合全包），NPO 下光引擎仍是可拆卸模块留在整机厂｜「某某是 NPO 独有」要验证，连接器厂商往往两条路线的产品并排卖。

### 其他赛道起手清单

- **风冷→液冷**：冷板/CDU/快接头 UQD/管路/工质/漏液检测/机柜改造/**供配电改造**（易漏）｜风扇与热管（减量）。注意 UQD 在冷板式是最紧缺高价值环节、在浸没式几乎不需要——押 UQD 等于押冷板路线。
- **液态锂电→半固态/全固态**：电解质（氧化物/硫化物/聚合物，路线互斥）/锂金属负极/**干法电极设备**/等静压设备/**超低露点干燥房**/隔膜（全固态下可能整个消失）/电解液与六氟（减量）/**注液机工位消失**（后段设备减量，市场只谈前段）
- **传统封装→先进封装**：中介层/TSV 设备/混合键合/临时键合解键合/载板/底填/**KGD 测试前移**/翘曲散热｜引线键合（减量）
- **HDD→SSD**：NAND/主控/DRAM 缓存/接口协议｜磁头盘片、主轴电机（减量）｜**服务器背板与线缆形态变化**（易漏）
- **铜互连→光互连**：光引擎/光纤/连接器/光源｜DAC 与 AEC（减量，注意 AEC 厂商的内部抵消）｜高速铜连接器（减量）

## 第 3 步：逐环节、逐路线判断

**对每条新路线独立判断**，不要合并。两条路线判断相同不代表可以合并写——归属可能完全不同（同样是"明显增量"，一条路线的价值归代工厂，另一条留在整机厂）。

七档枚举，只能用这七个字符串之一：

| 枚举值 | 含义 | 判断要点 |
|---|---|---|
| `⭐⭐ 纯新增` | 旧架构里不存在这个位置 | 最有价值的一档，但要严格——"用量变多"不算纯新增 |
| `⭐ 明显增量` | 用量/单价/技术门槛明显提升 | 要说清是量增、价增还是门槛提升，三者投资含义不同 |
| `○ 平移` | 总量基本不变，只是位置或形态改变 | 最容易被误判成利好 |
| `⚠️ 内部抵消` | 公司有得有失，净影响需自行判断 | 用于**同一家公司**跨环节的得失，不是环节本身的性质 |
| `❌ 减量` | 需求下降或消失 | 减的一侧同样要列公司，那是规避清单 |
| `❓ 待证实` | 方案未公开或存在矛盾证据 | 老实用这一档，比硬猜一个方向强 |
| `⊘ 不适用` | 该架构明确不需要这个环节 | 与"待证实"要分清：一个是知道不需要，一个是不知道 |

**这些字符串必须原样使用，不能加括号补充说明。**（英文对应：`⭐⭐ Net-new` / `⭐ Clear increase` / `○ Shift` / `⚠️ Internal offset` / `❌ Decrease` / `❓ Unconfirmed` / `⊘ Not applicable`） 任何限定条件（"WDM 方案下"、"仅 A 路线"）一律写进备注列。原因：xlsx 按单元格值精确匹配上色，带括号会匹配不上导致**静默漏色**；Excel 自动筛选也需要这一列是干净枚举值。脚本里有断言，写错直接报错。

**四个陷阱：**

1. **端口数/单元数没变的不是增量。** 先问「这个环节的物理数量变了吗」。
2. **"某某独有"要验证，不要推断。** 看到自己在写"X 独有"，去找反例（展会演示、产品页并列、MSA 文件）。
3. **总量与单价要分开。** 有些环节总量下降但单价跃升数倍，净额是增的；反过来也有。
4. **注意"判断相同但归属相反"的行。** 光看颜色看不出来，必须在备注和结论里点名。这往往是整张表最有价值的一行。

## 第 4 步：填公司，逐家回原始披露核实

**这一步最容易出错，也最能体现质量。** 美股/海外与 A 股**分两列**填，每家公司后跟一个口径标记：

| 标记 | 含义 | 可接受来源 |
|---|---|---|
| `★★★` | 官方**明示**该产品供这条路线 | 年报、半年报、公告、投资者关系活动记录表、业绩说明会、官网产品页、正式新闻稿、电话会讲稿与 Q&A |
| `◆` | 券商研报口径 | **不是官方**，不可与 ★★★ 并列 |
| `◇` | 产业纪要/专家访谈 | 可用于量价推算，不可用于赛道归属 |
| `○` | 有产品但官方归在**其他应用市场** | 官方来源，但限定词指向别处 |
| `△` | 仅通用产品描述，**无路线口径** | 官方来源，但没有任何限定词 |
| `⚠️` | 有反证、公司自身降温、或系推断 | 澄清公告、风险提示 |

**进度阶段**也要标：① 已有收入 → ② 量产批量交付 → ③ 小批量试产 → ④ 送样验证 → ⑤ 研发立项 → ⑥ 仅能力表态 → ⑦ ⚠️ 官方降温否认

### 核实的三个动作

**① 找到那句带路线限定词的原话。** `"有这个产品"` ≠ `"这个产品供这条路线"`，中间隔两层：

- **应用市场不同**——真实案例：某公司 AWG 被填进 CPO 表，查年报原文是「用于**骨干网和城域网**密集波分复用系统的阵列波导光栅」，写在**电信市场产品**项下，应标 `○` 而非 `★★★`
- **规格档次不同**——真实案例：某公司光纤阵列年报原话只有「广泛应用于各种光器件中的光纤阵列」，无 CPO/高通道/保偏任何限定词，而同行三家都有明示口径，四家并列会误读成同一档，应标 `△`

找不到带限定词的原话就降级，不要留白式并列。

**② 确认那句话是公司说的。** 互动易上「董秘您好，请问贵公司是否生产 X？」是**提问**不是回答。真实案例：某公司被标注「硅透镜验证中」，回查连续四份 IR 记录表没有一份提到硅透镜——那个词只出现在投资者提问里；而该公司真正有口径的是另一个产品、另一行。**把提问当口径，同时还漏掉了它真正该在的那一行。**

**③ 警惕多级推断和自媒体。** 股吧、财富号、雪球、公众号一律不算官方。最危险的是多级推断：「A 给 B 下了大单 → B 的供应商是 C → 所以 C 受益」。真实案例：某公司被广泛传为「进入英伟达 CPO 供应链、完成头部客户验证、北美 40% 份额」，查刚发布的半年报全文——「CPO」三字只出现一次且是在引用政府政策文件，公司自述零 CPO；同期外销仅 +2.71%，增长全来自内销翻倍，**叙事和财务方向相反**。

**交叉验证的好习惯**：真切入了新供应链，通常会在收入结构、合同负债或产能投资上留下痕迹。叙事与财务数据方向相反时，以财务为准。

### 公司自己泼的冷水要照录

澄清公告（「某信息不属实」）、「暂未形成规模化产品与营收贡献」、「处于技术研发与前期储备阶段」、「营收占比不足 1%」、收购/合作**终止**公告（尤其注意此前基于该收购的判断要一并撤回）——写进备注并标 `⚠️`。这类信息比利好更有价值，因为稀缺且几乎不被自媒体转载。

### 其他坑

证券简称变更（旧名检索会漏，填完顺手核）｜产品名与材料名混淆（一字之差会把公司填错行）｜同一家公司在不同赛道的能力不能外推｜核实会过期（新的半年报/IR 会改变结论，表上标日期，修订时重查）｜某环节 A 股确实空白就写「⚠️ 暂无 A 股有此产品口径」，空白本身是信息，比硬凑一家强。

**出表前自查**：这一格里每家公司我能说出原始出处吗？有没有把提问当回答？有没有把研报标成 ★★★？有没有多级推断？冷水记录了吗？空白环节是写「暂无」还是硬凑？

## 第 5 步：生成 xlsx

把数据组织成 JSON（格式见 `scripts/build_delta_xlsx.py` 开头注释），用脚本生成——不要手写 openpyxl：

```bash
python scripts/build_delta_xlsx.py delta.json "{RESEARCH_ROOT}/stocks/可插拔到NPO_CPO_环节增减量_20260817.xlsx"
```

脚本已处理枚举断言、条件上色、列宽、冻结窗格、筛选器，并自动打印路线间不一致的行和方向真正相反的行（第 6 步要用）。JSON 里 `"lang": "zh"` 或 `"en"` 决定输出语言；判断档位中英文写法都接受，输出统一成一种语言。

输出三页：**① 环节增减量对照**（主表，每条路线一列判断）、**② 关键结论**、**③ 图例与读法**（两套标记体系分块说明，脚本自动生成）。

## 第 6 步：写关键结论

结论页是这张表的灵魂，不要写成表格内容的复述。至少覆盖：

1. **路线互斥点**——两条路线判断方向真正相反的行有哪几个。脚本会自动打印出来。放第一条。
2. **待证实项聚类**——如果多行的某条路线都是 `❓`，检查它们是不是锁在**同一个未决问题**上。是的话点明，因为一旦证实会同时翻牌，这是信息价值最高的待查项。
3. **完全没有内部抵消的标的**——同时满足"该路线下是增量"且"主业不被替代"的公司，分美股/A股列。这是用户最想要的一份清单。
4. **判断相同但归属相反的行**——见第 3 步陷阱 4。
5. **本次修正与补漏**——修订已有表时，把改了什么、为什么改写清楚。研究表格的价值在于可追溯，不要静默修改。
6. **证据等级提醒**——哪些数字是官方的、哪些是推算的、哪些只有自媒体来源。附一份「官方点名过这条路线的公司」名单，通常很短且很有用。

## 常见失败模式

- **只列增量不列减量**——减的一侧是规避清单，往往更确定
- **把所有新架构相关公司都标成利好**——内部抵消那一档存在就是为了防这个，整机厂与模组厂在架构迁移里通常有得有失
- **漏掉设备、材料、测试三类**——这三类不在 BOM 里，但常常格局最集中、最没有内部抵消
- **枚举值加括号**——导致漏色和筛选器失效
- **公司归属靠印象填**——做完自查一遍每家的原始出处
- **结论页复述表格内容**——结论要给表格里看不出来的东西：互斥点、聚类、纯受益名单

保存到用户的股票研究文件夹（通常是 `stocks/` 子目录），格式：`{基准架构}到{路线A}_{路线B}_环节增减量_{YYYYMMDD}.xlsx`，例 `可插拔到NPO_CPO_环节增减量_20260817.xlsx`。修订版不要覆盖旧文件——用日期区分，研究结论的演变过程本身有价值。
